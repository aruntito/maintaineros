# MaintainerOS Governance

## 1. Purpose

This document describes how MaintainerOS is currently maintained and how project decisions are made. Governance should evolve with the project and its contributor community.

## 2. Current stewardship

MaintainerOS is currently stewarded by its founding maintainer, who is responsible for:
- Product direction and roadmap.
- Repository administration.
- Reviewing and merging contributions.
- Release decisions.
- Security response coordination.
- Community standards and contributor experience.

The project is not currently governed by an elected committee or independent foundation.

## 3. Decision-making

Routine decisions may be made by the maintainer and documented in relevant issues or pull requests.

Significant architectural or product changes should:
1. Describe the problem and affected users.
2. Present alternatives and trade-offs.
3. Invite feedback in an issue or discussion.
4. Record the decision and rationale.
5. Update relevant documentation.

Security-sensitive decisions may require confidential handling.

## 4. Contributions and maintainership

Contributions are evaluated on merit, quality, consistency, collaboration, and alignment with project principles. Commit access is granted only when there is a demonstrated need and appropriate trust.

A contributor does not automatically become a maintainer by submitting a particular number of pull requests.

As the project grows, maintainers may define additional roles, review responsibilities, and succession procedures in a public governance proposal.

## 5. Releases

The maintainer coordinates releases and is responsible for:
- Reviewing changes included in a release.
- Ensuring relevant tests and checks pass.
- Updating release notes.
- Communicating breaking changes and known limitations.
- Following documented security and provenance practices as they become available.

Release versions must reflect actual project stability.

## 6. Code of conduct

All project spaces are governed by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Maintainers may remove content or restrict participation when necessary to protect community safety and project operations.

## 7. Conflicts of interest

Contributors and maintainers should disclose material conflicts when they could affect a project decision. Decisions should prioritize project and community interests.

## 8. Changes to governance

Governance changes should be proposed publicly when practical, discussed with active contributors, and recorded in repository history. The current maintainer retains responsibility for repository administration until a documented transition occurs.

## 9. Project independence

MaintainerOS is an independent open-source project. It is not an official GitHub product and is not affiliated with GitHub, OpenAI, Anthropic, or other AI or developer-platform vendors.
